# 可访问性设计指南

## 1. 可访问性设计概述

### 1.1 设计理念

**核心原则**：技术应该为所有人服务，无论能力、年龄或环境如何。

**设计目标**：
- 让所有用户都能独立使用产品
- 提供多种交互方式满足不同需求
- 符合WCAG 2.1 AA级标准
- 超越合规，追求真正的包容性

### 1.2 目标用户群体

| 用户群体 | 特殊需求 | 设计考虑 |
|---------|---------|---------|
| 视觉障碍用户 | 屏幕阅读器、字体缩放 | 语义化标签、对比度 |
| 色盲用户 | 颜色辨识困难 | 颜色+图标双重编码 |
| 运动障碍用户 | 精细操作困难 | 大触控目标、键盘导航 |
| 认知障碍用户 | 信息处理困难 | 简洁语言、清晰导航 |
| 听力障碍用户 | 音频内容不可达 | 字幕、视觉提示 |
| 老年用户 | 视力下降、反应变慢 | 大字体、慢节奏 |

## 2. 视觉可访问性

### 2.1 颜色对比度标准

**WCAG AA级要求**：
- 正常文字：至少 4.5:1
- 大文字（18sp+）：至少 3:1
- UI组件：至少 3:1

**账单通配色对比度检查**：

| 颜色组合 | 用途 | 对比度 | 符合标准 |
|---------|------|--------|---------|
| #4CAF50 (主题色) on #FFFFFF | 按钮 | 3.2:1 | ✓ AA |
| #212121 (主文字) on #FFFFFF | 正文 | 16.1:1 | ✓ AAA |
| #757575 (次要文字) on #FFFFFF | 辅助文字 | 4.7:1 | ✓ AA |
| #FF5252 (错误) on #FFFFFF | 错误提示 | 3.8:1 | ✓ AA |
| #FFFFFF (按钮文字) on #4CAF50 | 按钮文字 | 3.2:1 | ✓ AA |

### 2.2 色盲友好设计

**问题**：仅依赖颜色传达信息

**解决方案**：
- **双重编码**：颜色 + 图标/文字
- **模式区分**：使用图案、形状辅助
- **高对比模式**：支持高对比度主题

**示例设计**：

**错误提示（色盲友好）**：
```
❌ 仅用颜色：
┌─────────────────────────────┐
│ 请输入金额                  │ ← 红色边框
└─────────────────────────────┘

✅ 颜色 + 图标：
┌─────────────────────────────┐
│ ⚠️ 请输入有效的数字         │ ← 图标 + 说明
└─────────────────────────────┘
```

**预算状态（色盲友好）**：
```
❌ 仅用颜色：
餐饮  ████████░░ 80%  ← 黄色

✅ 颜色 + 图标：
餐饮  ⚠️ ████████░░ 80%  ← 警告图标
餐饮  ✓ ████████░░ 50%  ← 健康图标
餐饮  ✗ ██████████ 100% ← 超支图标
```

### 2.3 字体缩放支持

**支持的缩放级别**：

| 级别 | 缩放比例 | 最小字体 | 用途 |
|------|---------|---------|------|
| 小 | 100% | 12sp | 标准显示 |
| 默认 | 100% | 14sp | 系统默认 |
| 大 | 125% | 16sp | 大号字体 |
| 特大 | 150% | 18sp | 老年模式 |
| 超大 | 200% | 20sp | 最大支持 |

**布局适配**：
```kotlin
// 支持系统字体缩放
Text(
    text = "¥3,245.80",
    fontSize = with(LocalDensity.current) {
        // 基于系统设置缩放
        (32.sp * fontScale).coerceIn(20.sp, 48.sp)
    }
)
```

### 2.4 深色模式支持

**设计原则**：
- 保持对比度符合标准
- 避免纯黑纯白，使用柔和灰度
- 保持品牌色一致性

**深色模式配色**：

| 元素 | 浅色模式 | 深色模式 | 对比度(深) |
|------|---------|---------|-----------|
| 背景 | #FFFFFF | #121212 | - |
| 卡片背景 | #FFFFFF | #1E1E1E | - |
| 主文字 | #212121 | #E0E0E0 | 15.1:1 ✓ |
| 次要文字 | #757575 | #B0B0B0 | 4.9:1 ✓ |
| 主题色 | #4CAF50 | #66BB6A | - |
| 分隔线 | #E0E0E0 | #2C2C2C | - |

## 3. 屏幕阅读器支持

### 3.1 语义化标签

```kotlin
        this.role = Role.Image
    }

```

### 3.2 内容描述规范

**组件内容描述标准**：

| 组件类型 | 描述要求 | 示例 |
|---------|---------|------|
| 按钮 | 动作 + 对象 | "保存记录"、"删除记录" |
| 图标按钮 | 功能说明 | "搜索记录"、"返回首页" |
| 图表 | 数据摘要 | "本月支出3,245.80元，餐饮占比37%" |
| 列表项 | 关键信息 | "餐饮，麦当劳，28.50元，今天12:30" |
| 输入框 | 标签 + 当前值 | "金额，28.50元" |
| 进度条 | 百分比 + 含义 | "预算使用65%，还剩1,750元" |

### 3.3 焦点管理

**焦点顺序**：符合逻辑的Tab顺序

```kotlin
// 确保焦点顺序正确
Column(
    modifier = Modifier.focusable()
) {
    // 1. 金额输入
    AmountInput(
        modifier = Modifier
            .focusRequester(amountFocus)
            .onKeyEvent { /* ... */ }
    )

    // 2. 分类选择
    CategorySelector(
        modifier = Modifier
            .focusRequester(categoryFocus)
            .onKeyEvent { /* ... */ }
    )

    // 3. 保存按钮
    Button(
        modifier = Modifier
            .focusRequester(saveFocus)
            .onKeyEvent { /* ... */ }
    ) { /* ... */ }
}
```

**焦点可见性**：
- 清晰的焦点指示器（2-4dp边框）
- 高对比度焦点颜色
- 动画过渡（200ms）

## 5. 触控目标尺寸

### 5.1 最小触控目标

**WCAG 2.1 AAA级要求**：
- 最小尺寸：44x44dp
- 推荐尺寸：48x48dp

**账单通触控目标规范**：

| 组件 | 尺寸 | 间距 | 说明 |
|------|------|------|------|
| 按钮 | 48dp高 | 16dp | 符合标准 |
| 图标按钮 | 48x48dp | 16dp | 内边距12dp |
| 列表项 | 最低56dp高 | - | 整行可点击 |
| 浮动按钮 | 56x56dp | 16dp | 更大便于点击 |
| 链接 | 最低44x44dp | 8dp | 扩大点击区域 |

### 5.2 点击区域扩展

**小图标点击区域扩展**：

## 6. 认知可访问性

### 6.1 语言简洁性

**写作原则**：
- 使用简单词汇（小学5-6年级水平）
- 避免专业术语
- 使用主动语态
- 一个句子一个想法

**示例对比**：

| 类型 | 不推荐 | 推荐 |
|------|--------|------|
| 错误提示 | "输入数据格式无效" | "请输入一个数字" |
| 操作说明 | "执行数据持久化操作" | "保存记录" |
| 帮助文档 | "配置分类参数" | "设置默认分类" |

### 6.2 信息架构清晰

**导航一致性**：
- 相同功能始终在同一位置
- 底部导航始终可见
- 返回按钮位置固定

**错误恢复路径**：
- 每个错误都提供解决方案
- 明确的返回路径
- 不丢失用户输入

**示例**：
```
错误恢复路径设计：

┌─────────────────────────────┐
│  保存失败                    │
│  网络连接失败，请重试        │ ← 明确说明
│                             │
│  ┌─────────────────────┐   │
│  │      重试            │   │ ← 解决方案
│  └─────────────────────┘   │
│  ┌─────────────────────┐   │
│  │      保存草稿        │   │ ← 备选方案
│  └─────────────────────┘   │
│                             │
│  [×] 取消                    │ ← 返回路径
└─────────────────────────────┘
```

### 6.3 帮助和提示

**上下文帮助**：
- 关键操作提供帮助图标(?)
- 点击显示简短说明
- 链接到详细帮助文档

**首次使用引导**：
- 气泡提示关键功能
- 可跳过的引导流程
- 引导记录在设置中可重复查看

## 7. 运动可访问性

### 7.1 减少动画支持

**尊重系统设置**：

```kotlin
// 检查减少动画设置
val reduceMotion = Settings.Global.getFloat(
    context.contentResolver,
    Settings.Global.TRANSITION_ANIMATION_SCALE,
    1.0f
) == 0.0f

// 条件渲染动画
if (!reduceMotion) {
    // 显示动画
    AnimatedVisibility(
        visible = isVisible,
        enter = fadeIn() + expandVertically()
    ) { /* ... */ }
} else {
    // 直接显示
    if (isVisible) { /* ... */ }
}
```

### 7.2 动画规范

**安全动画原则**：
- 避免快速闪烁（>3次/秒）
- 避免大范围移动
- 提供禁用选项
- 尊重"减少动画"设置

**动画时长限制**：

| 动画类型 | 最大时长 | 说明 |
|---------|---------|------|
| 页面切换 | 300ms | 平滑过渡 |
| 状态变化 | 200ms | 即时反馈 |
| 加载动画 | 1000ms | 循环动画 |
| 成功动画 | 400ms | 庆祝效果 |

## 8. 听觉可访问性

### 8.1 音频内容替代

**声音事件的视觉提示**：

| 声音事件 | 视觉替代 | 触觉替代 |
|---------|---------|---------|
| 保存成功 | Toast提示 | 震动 |
| 删除成功 | 动画 + Toast | 震动 |
| 预算警告 | 红色进度条 | 震动 |
| 记账提醒 | 通知横幅 | 震动 + 闪烁 |

### 8.2 震动反馈

**震动模式规范**：

| 事件 | 震动模式 | 持续时间 |
|------|---------|---------|
| 点击 | 轻微 | 10ms |
| 长按 | 中等 | 25ms |
| 保存成功 | 短震动 | 50ms |
| 错误 | 长震动 | 100ms |
| 警告 | 双震动 | 50ms x2 |

**代码示例**：
```kotlin
// 震动反馈
fun vibrate(context: Context, pattern: VibrationPattern) {
    val vibrator = context.getSystemService<Vibrator>()
    vibrator?.vibrate(
        VibrationEffect.createPredefined(pattern.effectId)
    )
}

enum class VibrationPattern(val effectId: Int) {
    CLICK(VibrationEffect.EFFECT_TICK),
    LONG_PRESS(VibrationEffect.EFFECT_CLICK),
    SUCCESS(VibrationEffect.EFFECT_HEAVY_CLICK),
    ERROR(VibrationEffect.EFFECT_DOUBLE_CLICK)
}
```

## 10. 可访问性设计总结

### 10.1 设计原则回顾

| 原则 | 说明 | 应用 |
|------|------|------|
| 可感知 | 信息必须以用户能感知的方式呈现 | 对比度、双重编码、触觉反馈 |
| 可操作 | UI组件必须可操作 | 触控目标、键盘导航、手势替代 |
| 可理解 | 信息和UI操作必须可理解 | 简洁语言、一致性、错误预防 |
| 健壮性 | 内容必须足够健壮 | 兼容辅助技术、向前兼容 |

### 10.2 优先级建议

**P0（必须）**：
- 颜色对比度符合WCAG AA
- 触控目标≥44x44dp
- 屏幕阅读器支持
- 键盘导航

**P1（重要）**：
- 字体缩放支持
- 深色模式
- 减少动画选项
- 震动反馈

**P2（增强）**：
- 高对比度模式
- 手势自定义
- 语音控制
- 多语言支持
